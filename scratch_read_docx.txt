1. Project Overview
Fresh Box ek mobile application hai (React Native) jisme customers ghar baithe vegetables, fruits, exotic vegetables, salad aur alkaline water ka subscription le sakte hain. Pura model package-based subscription hai — matlab user ek package buy karta hai aur us package ke according periodic deliveries milti rehti hain.
Application ka core idea yeh hai ki admin products aur packages define karta hai, aur users un packages ko subscribe karte hain apni needs ke hisab se. System automatically delivery dates calculate karta hai, wallet manage karta hai, aur notifications bhejta hai.

5.4  Fixed Vegetables — Rules
Admin fixed vegetables select karta hai apni product list mein se
Admin default quantity set karta hai (e.g., Aloo = 500gm)
Customer quantity slightly increase ya decrease kar sakta hai (within budget)
Customer fixed vegetables completely remove nahi kar sakta
Fixed vegetables hamesha har delivery mein aayengi
5.5  Seasonal Vegetables — Rules
Admin 10-15 vegetables ki pool define karta hai package mein
Admin decide karta hai ki user max kitne items choose kar sakta hai (e.g., 3 ya 4)
User apni marzi ke items choose karta hai pool mein se
User quantities set karta hai — lekin budget constraint apply hoti hai
User ko vegetables ki prices nahi dikhengi (internal calculation hoti hai selling price se)
Agar user budget exhaust kar le aur aur quantity badhana chahe — pehle kisi item se ghata le, phir badha sakta hai
Agar user pura budget use nahi kar paya — bacha hua amount wallet mein credit hoga
NOTE  IMPORTANT: Seasonal vegetables select karne se PEHLE user ko package ka full payment complete karna hoga. Payment ke baad hi customization screen open hogi.
5.6  Extra Items / Overage
Agar user package budget se zyada koi item add karna chahe — system instant additional payment request karega
Extra amount real-time payment se collect hoga usi moment mein
Ye extra amount normal wallet transaction se alag track hoga
6. Delivery Date Calculation Logic
Ye system ka ek critical aur complex part hai. Delivery dates automatically calculate hoti hain based on package services aur existing delivery schedule.
6.1  Gap Calculation
Formula: Gap (days) = 30 ÷ Number of Services
Services in Package
Gap Between Deliveries
Delivery Days in 30 Days
5 services
30 ÷ 5 = 6 days
Day 1, 7, 13, 19, 25
6 services
30 ÷ 6 = 5 days
Day 1, 6, 11, 16, 21, 26
10 services
30 ÷ 10 = 3 days
Day 1, 4, 7, 10, ... (every 3 days)
NOTE  SUNDAY RULE: Agar kisi calculated delivery date pe Sunday padta hai, toh wo delivery Saturday ko shift ho jaayegi. Aage ki saari dates same gap maintain karengi.
6.2  Date Suggestion Logic (New User ke liye)
Jab koi naya user koi package select karta hai, system randomly dates suggest nahi karta. Logic yeh hai:
System check karta hai ki us specific package type (e.g., Nano) ke existing customers ki NEXT delivery dates kya hain
Sirf wahi dates user ko suggest ki jaati hain jis din pehle se usi package type ki delivery already ho rahi hai
User in suggested dates mein se apni start date choose karta hai
Baaki dates same gap formula se automatically calculate ho jaati hain
NOTE  BENEFIT: Isse ek hi route pe multiple customers ki delivery ek din mein ho jaati hai — delivery efficiency badh jaati hai aur cost kam hota hai.
6.3  Service Completion & Recharge
Jab user ki saari services complete ho jaayein — app user ko recharge notification bhejega
Recharge ke baad same logic se agli 30 days ki delivery dates calculate hongi
Recharge ki date same suggested date logic follow karegi

8. Wallet System
Har user ka ek internal wallet hoga. Package payment wallet mein credit hoti hai aur har delivery ke baad debit hoti hai. Ye system transparency provide karta hai aur refunds easy banata hai.
8.1  Wallet Flow — Step by Step
User package buy karta hai → Full amount wallet mein credit
Delivery boy delivery complete mark karta hai → Per-service amount wallet se deduct
IMPORTANT: Amount tabhi deduct hoga jab delivery confirmed ho — pehle nahi
Agar 5 services hain Rs. 750 ka package → har delivery pe Rs. 150 deduct

8.3  Credit / Postpaid Feature (Loyalty)
Agar koi user 2 consecutive months successfully subscribe kar chuka hai...
...toh 3rd month mein bina recharge ke service milti rahegi
User ke wallet mein 'Due Amount' clearly dikhega

17. Business Rules — Quick Reference
Ye saare critical rules hain jo development mein kabhi bhi miss nahi hone chahiye:
Package & Pricing Rules
Package price HAMESHA total vegetable selling cost se zyada honi chahiye — hard validation at save time
Seasonal vegetables select karne se PEHLE payment mandatory — no exceptions
User ko products ki purchase/selling price kabhi nahi dikhni chahiye
Extra quantity/item ke liye instant additional payment leni hogi
Delivery Date Rules
User sirf system-suggested dates hi select kar sakta hai — random date selection allowed nahi
Suggested dates sirf us package type ki existing delivery dates se aayengi
Sunday padne pe delivery automatic Saturday pe shift ho jaayegi
Gap formula: 30 ÷ services = days between deliveries
Wallet Rules
Amount deduct tabhi hoga jab delivery boy delivery confirm kare — pehle nahi
Remaining balance next recharge mein adjust hoga
Return approved hone pe amount wapas wallet mein aayega
2 month loyal users ko 3rd month credit pe milegi — 4th month se band agar payment nahi
Pause Rules
Monthly: Max 15 din per cycle, balance carry karta hai usi cycle mein, next cycle fresh 15 din
Yearly: Sirf 1 baar max 45 din, early restart pe bhi balance waapis nahi milta
Restart date bhi system-suggested hogi — same package type ki existing delivery date
Pause ke dauran koi delivery nahi, koi wallet deduction nahi
Notification Rules
Delivery se 1 din pehle raat 8 PM ke baad notification jaayegi
User sirf delivery se 1 din pehle raat 8 PM tak changes kar sakta hai
8 PM baad order lock — us delivery ke liye koi changes nahi
User ne kuch nahi kiya — system last highest-frequency order auto-repeat karega
